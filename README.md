# 일잘러 문장

한국 직장인을 위한 업무 문구 작성 앱입니다. 기본은 브라우저에서 동작하는 템플릿이며, 사용자가 원할 때만 Gemini, Claude, GPT 또는 OpenAI 호환 커스텀 API에 문구 다듬기를 요청합니다. 로그인·데이터베이스 없이 사용할 수 있습니다.

아래 이미지는 GPT 브라우저에서 실행한 앱의 실제 첫 화면입니다.

## UI 사용 흐름

앱은 **상황 선택 → 정보 입력 → 문구 확인**의 3단계로 구성됩니다. 상단 진행 표시와 이전 단계 버튼으로 현재 위치를 확인하고 내용을 바꿀 수 있습니다.

1. **상황 선택** — 연차·병가 신청, 업무 보고, 일정 조율, 자료 요청 중 필요한 항목을 고릅니다.
2. **정보 입력** — 선택한 상황에 필요한 정보만 표시됩니다. 받는 사람(상사·동료·외부 회사)과 말투 강도를 함께 선택합니다. AI 설정이 완료되어 있으면 선택적으로 AI 다듬기를 켤 수 있고, 실제 전송 전 제공자와 전송 항목을 확인하는 안내가 표시됩니다.
3. **문구 확인** — 이메일과 메신저 탭을 오가며 제목과 문구를 직접 수정합니다. 제목·본문·이메일 전체·메신저 문구를 각각 복사하거나, 톤을 바꾸고 이전 초안으로 되돌릴 수 있습니다.

AI 설정은 우측 상단 **AI 설정**에서 제공합니다. API 키는 설정 서버에만 전송되며 앱은 브라우저 저장소에 입력값을 보관하지 않습니다. 첫 화면 상단의 안내와 결과 화면의 발송 전 체크 메시지에서 개인정보 보호 안내를 확인할 수 있습니다.

## 실행

Node.js 20 이상을 설치한 뒤 프로젝트 폴더에서 실행합니다.

```bash
npm install
npm run dev
```

기본 주소는 `http://127.0.0.1:5173`입니다. 개발 서버와 미리보기 서버는 이 컴퓨터에서만 접속할 수 있습니다. 템플릿 작성은 API 서버나 API 키 없이도 동작합니다.

## AI 제공자 설정

1. 별도 터미널에서 `npm run server`를 실행합니다.
2. 앱 상단의 **AI 설정**을 열어 제공자, API 키, 모델을 선택하고 **연결 테스트**를 누릅니다. 테스트는 외부 제공자에 짧은 요청을 보내며 하루 호출 한도에 포함됩니다.
3. 연결이 성공하면 **설정 저장**을 누릅니다.
4. 입력 화면의 **필요할 때 AI로 한 번 더 다듬기**를 선택하면, 실제 전송 직전에 제공자와 전송될 항목을 확인합니다. 확인한 경우에만 해당 입력을 선택한 제공자에 보냅니다. 취소하면 템플릿 작성만 사용합니다.

| 제공자 | 기본 API 주소 | 기본 모델 |
| --- | --- | --- |
| GPT (OpenAI) | `https://api.openai.com/v1/chat/completions` | `gpt-6-luna` |
| Claude (Anthropic) | `https://api.anthropic.com/v1/messages` | `claude-haiku-5-5` |
| Gemini (Google) | `https://generativelanguage.googleapis.com/v1beta` | `gemini-3.8-flash` |
| 커스텀 API | 직접 입력 | 직접 입력 |

커스텀 API는 OpenAI 호환 Chat Completions 형식이어야 하며, 주소는 `/chat/completions`로 끝나야 합니다. 다른 요청·응답 형식의 API는 현재 지원하지 않습니다.

## 키 저장과 서버 보호

설정창에서 저장한 키는 프로젝트의 `.env.local`에 저장됩니다. 이 파일은 `.gitignore`에 포함되어 저장소에 커밋되지 않으며, 서버 응답이나 브라우저 저장소에는 키를 기록하지 않습니다. `.env.local`은 평문 비밀 파일이므로 다른 사람과 공유하지 말고, 서버 계정과 파일 접근을 보호하세요. 환경변수 방식이 필요한 경우 `.env.example`을 `.env`로 복사해 `AI_PROVIDER`, `AI_API_KEY`, `AI_API_URL`, `AI_MODEL`을 입력하면 됩니다.

AI 서버는 기본적으로 `127.0.0.1`에만 바인딩됩니다. 외부 배포 시 HTTPS 리버스 프록시와 정확한 `FRONTEND_ORIGIN`, 32자 이상의 임의 `APP_ACCESS_TOKEN`을 설정하세요. 프록시가 다른 서버/컨테이너에서 실행될 때만 내부 네트워크에서 접근 가능한 주소로 서버를 바인딩하고, 프록시 외부에는 노출하지 마세요. 앱은 접근 코드를 화면에서 요구하며 코드는 브라우저 메모리에만 유지됩니다. 프론트엔드와 API 서버가 다른 도메인이면 빌드 시 `VITE_API_BASE_URL`도 지정합니다.

## 호출 및 비용 제한

AI 설정 화면에서 하루 호출 상한을 1~500회로 지정합니다. 문구 생성과 연결 테스트는 이 상한을 함께 사용하며 한국 시간 날짜별 호출 수는 `.ai-usage.json`에 저장됩니다. IP별 분당 요청 제한도 적용합니다. 이 제한은 호출 횟수 기준이며 금액 한도는 아닙니다. 실제 비용 상한은 각 제공자 계정의 결제·사용량 설정에서도 지정하세요.

## 사용 흐름과 개인정보

1. 상황을 고릅니다.
2. 필요한 정보와 받는 사람, 간결·기본·부드럽게·매우 정중한 말투를 고릅니다. 필수 항목이 모두 입력되어야 작성할 수 있고, 각 항목은 2,400자까지 입력할 수 있습니다. 연차 기간, 회의 일정, 자료 기한은 달력으로도 입력할 수 있습니다. 시간차는 시작·종료 시각이 필요합니다.
3. 이메일 제목·본문과 메신저 문구를 확인·수정합니다. 제목/본문/전체/메신저별 복사와 톤 변경, 이전 초안 복구를 지원합니다. 입력 단계로 돌아가도 입력 내용은 유지됩니다.

AI 설정 창에서 **키 삭제**를 누르면 `.env.local`의 활성 API 키를 비우고, AI를 선택하지 않는 기본 템플릿 모드로 돌아갑니다. 직접 작성한 내용은 브라우저 저장소나 서버 파일에 보관하지 않습니다. AI를 선택하면 해당 요청에 포함한 입력만 설정한 제공자에게 전달되므로 민감정보를 입력하지 마세요.

설정 창은 닫기 버튼, 배경 클릭 또는 `Esc` 키로 닫을 수 있습니다.

## 구현 기능

- 연차·병가, 업무 보고, 일정 조율, 자료 요청
- 상사·동료·외부 회사별 말투 적용
- 이메일 제목/본문과 메신저 문구, 직접 수정 및 복사
- 더 정중하게·더 짧게·더 부드럽게, 다시 생성
- AI 요청 실패 시 템플릿 문구로 대체
- 입력값은 앱의 브라우저 저장소나 데이터베이스에 저장하지 않음
- 민감정보 입력 주의와 발송 전 확인 안내
- 상황 선택 → 정보 입력 → 결과 확인의 3단계 흐름과 이전 단계 복귀

## 테스트와 빌드

템플릿 생성과 수신자별 표현에 대한 자동 테스트와 프로덕션 빌드는 다음 명령으로 확인합니다.

```bash
npm test
npm run build
```

## 배포 점검

이 프로젝트는 기본적으로 한 사용자가 자기 컴퓨터에서 실행하는 구성을 목표로 합니다. 외부에 배포할 때는 다음 사항을 확인하세요.

- 프론트엔드와 AI 서버 앞에 HTTPS를 제공하는 리버스 프록시를 둡니다.
- `.env`에 `HOST=127.0.0.1`을 유지해 AI 서버를 프록시 밖에서 직접 접속할 수 없게 하고, 프록시가 같은 호스트에서 접근하도록 구성합니다. 프록시와 서버가 분리된 경우에만 필요한 네트워크 경로를 열어 주세요.
- `FRONTEND_ORIGIN`을 실제 프론트엔드의 정확한 출처로 지정하고 32자 이상의 임의 `APP_ACCESS_TOKEN`을 설정합니다. 토큰은 안전한 경로로 사용자에게 전달하고 코드 저장소에 넣지 마세요.
- 빌드할 때 `VITE_API_BASE_URL`을 API 서버의 HTTPS 주소로 설정합니다. 이 값은 공개 가능한 주소여야 하며 비밀키를 넣으면 안 됩니다.
- `.env.local`과 `.env`는 비밀 파일로 취급하고 백업·배포 로그·소스 제어에 포함하지 않습니다. 키는 제공자별 계정의 사용량 한도도 함께 지정하세요.
- 로그에 입력 문구, API 키, 접근 코드를 기록하지 마세요. 현재 서버는 요청 본문을 기록하지 않습니다.

호출 횟수 파일과 분당 IP 제한은 단일 서버 프로세스 기준입니다. 여러 서버 인스턴스로 확장하려면 공유 저장소와 중앙 제한 기능을 별도로 구성해야 합니다. 컨테이너 등 임시 디스크 환경에서는 `.ai-usage.json`을 보존할 영속 디스크를 연결하거나 서버 재시작 시 호출 수가 초기화될 수 있음을 고려하세요.
